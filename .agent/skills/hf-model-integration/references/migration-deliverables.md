# 迁移交付物：ckpt 转换与脚本生成

迁移除了模型适配器本身，还要交付能让别人**独立跑起来**的东西：权重转换、
recipe、启动与测试脚本，最后汇成迁移报告。本页给这几项的要求与检查点。

## ckpt 转换

把上游（HF）权重转成框架可加载的形式。

| 要求 | 说明 |
|---|---|
| 名称映射完整 | 上游每个权重张量都要有去处；多余/缺失都要显式记录原因，不静默丢弃 |
| 分片规则正确 | 与 TP/EP 的切分一致；转换产物在目标并行度下可直接加载 |
| 形状与 dtype 核对 | 转换后逐张量核对 shape/dtype，不靠加载不报错当通过 |
| 可逆性/可核对 | 至少能抽样核对若干张量数值与上游一致 |
| 不改写源权重 | 转换只读上游、只写新产物 |

**检查点**：转换脚本对缺权重/多权重/形状不符要**显式失败并指名**，不得
吞掉。

## recipe（训练 YAML）

| 要求 | 说明 |
|---|---|
| 组件行为走配置字段 | 不用环境变量开关组件；环境变量留给基础设施 |
| 并行度可配 | TP/DP/EP/CP/PP 与序列长度在 recipe 里显式 |
| 默认可跑 | 默认值要能在声明的硬件上跑起来，不是占位 |

## 启动脚本

| 要求 | 说明 |
|---|---|
| 单机 / 多机各一份 | 多机的 rank/地址/端口来源要清楚 |
| 缺输入时明确失败 | 缺权重/数据/配置要报清楚缺什么，不要跑一半才挂 |
| 不含个人环境硬编码 | 路径/账号可配；集群特定内容留在调用方 |

## 测试脚本

| 要求 | 说明 |
|---|---|
| UT 可无卡运行 | 结构/契约类测试放 `tests/ut`，CPU 可跑 |
| UT 只依赖已安装包与测试树 | 门禁会把 `tests/` 单独拷贝，不要按固定层级去仓库根取仓外文件 |
| ST 多卡 | 走既有 ST 机制，声明所需卡数 |

## 迁移报告

用 `templates/migration-report.md`：迁移范围、适配项清单、产出物、
功能/精度/性能验证、使用限制、变更记录。精度口径走
`rules/precision-acceptance.md`，性能/显存拆解交 `profiling` 与
`memory-analysis` skill，报告里引用其结论即可。

## 纪律

- 每个数字附命令 + commit + 环境；未实测标 `[待测]`。
- 「能加载/能跑」不等于「对」：权重转换和并行适配都要有可核对的证据。
