# 集群故障分类与判据

把症状归到故障类，再按该类的判据取证。总原则：**区分「在等」与「出错」**
——阻塞在集合通信的 rank 多半是受害者，真凶是那个没到场的 rank。

## HCCL 超时

| 判据 | 说明 |
|---|---|
| 报错含 HCCL timeout / execute timeout | 某 rank 等集合通信超时 |
| 各 rank 首错时间戳 | 最早那个 rank 往往是真凶（它没到场或先挂）|
| 是否首跑新 shape | 首次 AOT 编译极慢会撞执行超时，像算子故障——查 kernel 缓存时间戳/CPU 占用；提高超时后复测 |

**要点**：超时是症状。先确认「谁没到场」，再问它为何没到场。

## 集群卡死（hang，无报错）

| 取证 | 说明 |
|---|---|
| py-spy 各 rank 栈 | 看每个 rank 停在哪：都停在同一集合通信=有 rank 没进；停在不同点=序列不一致 |
| plog | 是否有设备侧错误但未上抛 |
| 是否有 rank 已退出 | 退出的 rank 导致其余永等 |

## 部分 rank 异常退出

| 判据 | 说明 |
|---|---|
| 退出 rank 的日志末尾 | 真因在它那里（OOM / 设备错 / 断言）|
| 其余 rank 的通信报错 | 下游症状，别据此定因 |
| torchrun 输出截断 | 部分 rank 看似无 Traceback 是截断假象，去各 rank 日志文件取全栈 |

## 集合通信序列不一致

| 判据 | 说明 |
|---|---|
| 各 rank 停在不同的集合通信调用 | 控制流分叉（条件分支依赖 rank 本地数据）|
| 通信算子类型/顺序对不上 | 某些 rank 多调/少调一次 |

**要点**：数据相关的条件分支若各 rank 判断不同，就会错位；查分支条件是否
rank 间一致。

## 通信域错配

| 判据 | 说明 |
|---|---|
| group 与并行配置不符 | TP/DP/EP/CP/PP 的域构建或传参错 |
| 同一通信在不同 rank 用了不同 group | 域创建顺序/条件不一致 |

## 设备 / 节点 / 链路 / 调度基础设施

| 判据 | 说明 |
|---|---|
| plog 有 `PrintCoreInfo` + 解码 `errorStr:` | 某个核真算错（设备侧真故障）|
| plog 只有 notify 的 `Report*Error` | 在等别人，是常规流量，不是故障证据 |
| npu-smi 设备异常 / 链路 down | 硬件或网络 |
| 端口被占、EI 类组网报错 | 多半是**其他用户的活任务**占着 device 网口——查全用户进程表；绝不清理他人任务，换节点或等释放 |

## 取证纪律

- 每条结论附 rank / 文件 / 时间戳 / 采集命令。
- 跨 rank 按时间戳排序定首错；晚于首错的多为拆除噪声。
- 只读：不杀他人进程、不重置设备、不改共享节点配置。
- 代码修复转 `debug` skill，先单卡/单机验证再上集群。
