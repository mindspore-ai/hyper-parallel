显存拆解报告

快照：（）

规则版本：memory breakdown-dimensions v2（按 torch_npu 2.9.0 实采字段解析）。 单位 MiB。

一、总量与碎片

项MiB说明

快照是取样瞬间，不等于峰值。步后取的快照里没有任何激活； 实测即便在 backward 中途取样，活跃量仍低于 max_memory_allocated。 峰值构成需要在峰值时刻取样，或用 device_traces 回放。

二、按类别

类别MiB占活跃量

类别由记录栈按规则判定：torch/optim 帧→优化器状态、 模块 .to() 转换→参数、native 帧含 AccumulateGrad→梯度 （梯度由 C++ autograd 引擎分配，没有任何 Python 帧，这是唯一可用信号）、 最内层自有代码帧在 forward 内→激活。

三、最大的活跃块

MiB类别调用点

调用点取最内层不在 site-packages 内的 Python 帧——记录栈是 最内层优先，而其最内层几帧是快照机制自身（unwind / CapturedTraceback / ??），取 frames[0] 会让 每个块都归到同一处。

四、跨快照增长（泄露 vs 一次性峰值）

项Δ MiB说明

单份快照分不清「泄露」与「一次性大分配」：某类别在连续 step 间持续 增长才是泄露。采集默认 dump step 1–3，正好可两两比对。

五、一致性校验

校验结果明细

校验不通过时对应数字不可直接采信。退出码：0=全通过，2=有不通过项。

六、结论与下一步

拆解只定位占用来源；省显存的手段见 perf-playbook skill （重计算/offload/分配器配置等），性能影响须同时量化。
