Parser rules: memory breakdown-dimensions v2, based on fields captured with torch_npu 2.9.0. Units are MiB.

1. Totals and fragmentation

MetricMiBNotes

A snapshot represents one instant, not necessarily the peak. Observed post-step snapshots contain no activations; even mid-backward snapshots had less active memory than max_memory_allocated. Peak composition requires a capture at the peak or replay of device_traces.

2. Allocation categories

CategoryMiBShare of active memory

Categories are inferred from recorded stacks: torch/optim frames indicate optimizer states; module .to() conversions indicate parameters; native AccumulateGrad frames indicate gradients. The C++ autograd engine allocates these gradients with no Python frame, so the native symbol is the available signal. An innermost user-code frame in forward indicates activations.

3. Largest active blocks

MiBCategoryCall site

Attribution uses the innermost Python frame outside site-packages. Recorded stacks are innermost-first, but their first frames belong to the capture machinery (unwind, CapturedTraceback, or ??). Using frames[0] would assign every block to that same internal location.

4. Growth across snapshots (leaks versus transient allocations)

MetricΔ MiBNotes

A single snapshot cannot distinguish a leak from a large transient allocation. Inspect continued category growth across consecutive steps. The default captures cover steps 1–3 for pairwise comparison.

5. Consistency checks

CheckResultDetails

A failed check limits confidence in the affected measurements. Exit codes: 0 = all checks passed; 2 = one or more checks failed.

6. Findings and next step

The breakdown identifies memory consumers. Use the perf-playbook skill to select recomputation, offload, allocator configuration, or other memory optimizations. Measure their performance impact as well.
