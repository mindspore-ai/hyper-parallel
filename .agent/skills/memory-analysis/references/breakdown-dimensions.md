# 显存拆解维度与分类规则

把快照拆成静/动态、按阶段、按 module 的激活，并估算重算收益。归类按**明确
规则**（可复现）。内部特有口径标 `[待对齐]`。

## 静态 vs 动态

| 类别 | 归入 | 判定规则（默认）|
|---|---|---|
| **静态** | 参数、优化器状态、常驻 buffer | 训练全程常驻、跨 step 不释放的块；调用栈指向参数/优化器分配点 |
| **动态** | 激活、临时张量 | 前向分配、反向释放的块；调用栈指向 forward/backward 计算点 |

## 阶段（前向 / 反向 / 优化器更新）

按分配事件的时间区间与调用栈归入阶段：

| 阶段 | 信号 |
|---|---|
| 前向 | forward 调用栈内的 alloc，active 量上升段 |
| 反向 | backward 调用栈，激活逐步 free、梯度 alloc |
| 优化器更新 | optimizer.step 区间的 alloc/free（状态读写、临时）|

> 峰值通常落在前向末 / 反向初（激活最满 + 梯度开始）；峰值定位要指出落在
> 哪个阶段、哪个调用点。

## 峰值构成（Tensor 粒度）

峰值时刻的 active 块按 size 降序列出，每块附调用栈归因（哪个 module / 哪种
张量：激活 / 参数 / 梯度 / 优化器状态）。这是「峰值显存拆到 Tensor 粒度」。

## 激活按 module + 重算收益

- 按调用栈的 module 前缀，把动态激活显存聚合到 module。
- **细粒度重算收益估算**：对一个 module，重算能省的 ≈ 其前向激活常驻量
  （反向前需保留的部分）减去重算所需的输入保留量。规则化估算，给出
  每个 module「重算可省显存」排序，供 perf-playbook 选是否重算该 module。
- `[待对齐]`：内部对「哪些激活必须保留 / 可重算」的精细口径。

## 碎片 / 泄露

- **碎片**：`reserved - active_peak` 与 inactive 块分布；碎片率高→考虑
  分配器策略 / 预热分配。
- **泄露**：跨 step active 单调增长的块集合 + 其调用栈。

## 复现纪律

- 分类规则有版本；报告写明版本，换规则即换口径。
- 同一份快照产出同一份拆解。
- 本 skill 定位显存问题；选手段（重算/swap/offload）交 `perf-playbook`。
