# 精度问题定位：nan / loss spike / 不收敛

常见精度问题的定位思路。总原则：**定位首个异常，不追末端症状**；先用
`align-flow.md` 的 dump 比对锁定首个超阈点，再按症状类别细查。专有判据标
`[待对齐]`。

## NaN / Inf

1. **首次出现位置**：开 msprobe 的溢出检测（overflow check），定位第一个
   产出 NaN/Inf 的 API/module 与 step——下游全 NaN 是传播，首个才是源。
2. **常见源**：除零 / log(0) / 上溢的 exp / 未掩码的 -inf 参与 softmax /
   fp16 溢出 / 非法 index gather。
3. **区分环境 vs 逻辑**：先确认不是设备/环境崩（如无卡机触发的设备初始化
   报错不是数值 NaN）；再看是否特定输入/形状触发。
4. 修复后回归：同输入复跑，确认该点不再 NaN 且下游恢复。

## Loss spike（loss 突刺）

1. **定位 spike step**：记录 loss 曲线，锁定突刺 step 与其前一个正常 step。
2. **grad_norm 对照**：spike 常伴 grad_norm 跳变；查是否梯度爆炸、
   lr/warmup 异常、某 batch 数据异常。
3. **是否可复现**：固定种子复跑，spike 是否在同 step 复现——可复现=确定性
   成因（代码/数据），不可复现=非确定性（通信/随机/竞态）。
4. **缩小范围**：关掉可疑特性（如某融合/重算）同口径复跑，看 spike 是否消失
   （能证伪的对照，不是翻日志猜）。

## 不收敛（loss 不降 / 平线 / 发散）

1. **首 step 与基线对齐**：首 step loss 若已偏离基线，是前反向正确性问题，
   走 dump 比对定位首个异常 module；首 step 对、后续发散，偏优化器/lr/数据。
2. **梯度是否到达**：确认被训参数真的拿到非零梯度（梯度断流 = 平线恒定）；
   确认参数在 optimizer param group 里。
3. **目标/标签对齐**：监督目标的移位/mask 是否正确（常见：labels 预移位 +
   模块内再移位的双重 shift 导致恒不收敛）。
4. **数值口径**：精度降级（如评分 bf16）导致选择/路由翻转，表现为缓慢
   不收敛；比对首个异常可暴露。

## 产出

每个定位结论写进 `templates/precision-report.md`：首个异常点、证据（dump
比对/溢出位置/对照实验，附命令+commit+环境）、下一步修复意见。

## 纪律（与 precision-acceptance 同源）

- 正面验证：先确认干预真生效再下「无效」结论；负结果最易是假的。
- 能证伪的对照：关特性同口径复跑排除嫌疑，别靠巧合与翻日志。
- bf16 并列差 < 1 ulp 是物理噪声不是 bug。
