The three additive components come from step_trace_time.csv and sum to Stage. The optimizer interval comes from Optimizer.step# in operator_details.csv. It is a subset of Computing, shown separately for attribution and excluded from the sum.

2. Device execution by Core Type

Derived from Core Type in op_statistic.csv. Durations cover the entire capture window, not one step.

3. AI_CPU operator-fallback hotspots

Operator typeDuration (us)Share

HCCL launch kernels (*AicpuKernel) are excluded. They execute on AI CPU as communication work, not operator fallback. For genuine fallback, such as integer ArgSort, use the perf-playbook skill to select an intervention.

4. Communication breakdown

MetricValueNotes

Derived from communication.json. Per-step aggregates use Total Op Info; individual-operator enumeration excludes that key. A large Wait share indicates synchronization waiting rather than transfer bandwidth. Communication groups map to parallel dimensions through parallel_group_info in profiler_metadata.json, shown in the capture environment above.

5. Consistency checks

CheckResultDetails

A failed check limits confidence in the affected measurements. Exit codes: 0 = all checks passed; 2 = one or more checks failed.
