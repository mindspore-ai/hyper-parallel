# 拆解维度与分类规则

步时拆成四个维度，每个维度的归类按**明确规则**（可复现）。另支持 Layer /
Module / 算子三种视角的汇总。分类规则随实践补充；内部特有口径标 `[待对齐]`。

## 四维

| 维度 | 归入 | 判定规则（默认）|
|---|---|---|
| **计算** | Cube / Vector / FA（FlashAttention） | 按 `OP Type` / `Task Type=AI_Core` 归类：矩阵乘类→Cube、逐元素/归约类→Vector、注意力融合类→FA；AI_CPU 算子单列为回退热点 |
| **通信（未掩盖）** | TP / DP / EP / CP / PP | 通信算子按其通信域 group 映射到并行轴（需并行配置）；仅计入未被计算掩盖的部分 |
| **Free** | 下发气泡 / 等待 / 空隙 | step 时间线里既非计算也非通信占用的空档 |
| **优化器更新** | optimizer step | 优化器相关算子段（含参数更新、状态读写、offload 往返）|

> 占比以各维度耗时 / 步时。采集开销不计入真实步时，拆解取相对占比。

## 通信算子 → 并行轴映射

通信算子本身只知道 group，需结合并行配置把 group 映射到轴（TP/DP/EP/CP/PP）。
`breakdown.py` 接受一个可选的 group→轴映射（来自并行配置 dump）；无映射时
按通信域大小/算子类型启发式归类并标注不确定。`[待对齐]`：内部对特定通信域
的轴归属口径。

## 视角汇总

| 视角 | 含义 | 来源 |
|---|---|---|
| **算子** | 逐算子/按算子类型耗时 Top-N | op_summary / op_statistic |
| **Module** | 按 module 名前缀聚合（需 profiler 带 module 标记）| timeline / module 标记 |
| **Layer** | 按层聚合（module 之上）| module 汇总再按层正则归并 |

## 复现纪律

- 分类规则有版本：报告里写明用的规则版本，换规则即换口径，要重算。
- 同一份 trace 必须产出同一份拆解；拆解是规则结果不是判断。
- AI_CPU 回退、未掩盖通信、Free 气泡是三类最常见可动的瓶颈，优先标出，
  交 `perf-playbook` 选手段。
