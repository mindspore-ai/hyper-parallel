# CANN / PTA 常用环境变量

影响性能与调试的常用环境变量。**环境变量只用于基础设施与调试**；组件行为
应由 recipe/配置字段驱动，不要把功能开关塞进环境变量（框架源码约定）。

> 本表是方法性参考，登记项随实践补充。每个变量写清作用、取值、适用场景与
> 坑；拿不准影响的变量不要在生产 recipe 里设。

## 登记项（每个变量填）

| 字段 | 说明 |
|---|---|
| 变量名 | 环境变量名 |
| 作用 | 它改变什么行为 |
| 取值 | 典型/推荐取值 |
| 适用 | 什么场景设、什么场景别设 |
| 坑 | 已知副作用或误用后果 |

## 已沉淀的坑（实践得来）

- **首跑 AOT 编译耗时极长**：新算子形状首次 AOT 编译可达数十分钟，超过默认
  执行超时会整轮报错、极像算子故障。新 shape 首跑把执行超时上调（如
  `HCCL_EXEC_TIMEOUT=7200`）；长时间无输出先确认是否在编译（查 kernel
  缓存目录时间戳 / 进程 CPU 占用），不要当死锁改代码。
- **共享盘并发编译同一 .so**：多 rank 并发首次编译同一算子 .so 会
  `ld: final close failed: Input/output error`；先串行编一次。
- **调试日志可见性**：训练配置下 `logger.warning` 未必可见，调试用直通
  输出确认路径是否生效，别靠「没看到告警」反推。
- **CPU UT 节点的 torch_npu**：CPU 门禁机装了 torch_npu 但无卡，`backward`
  经非重入 checkpoint 重算会触发 npu autocast 懒初始化而崩（`aclInit`
  507008）；CPU 用例要么跳过设备侧重算、要么存根该探测。

## 口径纪律

- 调优的 A/B 必须在**同一环境变量集**下对比；改了变量就是改了口径，要重测。
- 设任何性能相关变量都在调优总结里记录其值（`templates/tuning-summary.md`）。
