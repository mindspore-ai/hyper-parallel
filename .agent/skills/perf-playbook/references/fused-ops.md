# 融合算子参考

融合算子通过把多个小算子合并、减少中间张量与下发，缓解计算瓶颈。接入前
必须确认**算子约束**是否满足——不满足则逐调用回退到参考实现、收益归零且
日志上与生效态无法区分（必须看正面生效标记）。

> 本表是方法性参考与登记约定，不是穷举清单。新增融合算子接入时在此登记其
> 约束与适用场景，并在对应特性文档的性能验证里给出单层/端到端实测。

## 登记项（每个融合算子填）

| 字段 | 说明 |
|---|---|
| 算子名 | 下发的 custom op 名 |
| 约束 | 支持的头数 / head_dim / dtype / 形状 / 序列长度上限等 |
| 适用场景 | 替换哪条计算链、针对哪类瓶颈 |
| 生效标记 | 如何正面确认走了融合路径（engaged 置位 / INFO 日志）|
| 回退条件 | 约束不满足时的行为（逐调用回退参考实现）|
| 实测 | 单层加速比 + 端到端收益（同节点背靠背），附命令/commit/环境 |

## 接入通则

- **生效必须正面验证**：回退跑与融合跑都不产生告警，日志上无法区分；凡
  测量先确认生效标记（如 `engaged=1`），由被测进程自己写出。
- **约束门控要显式**：头数/dtype/形状/长度不满足时逐调用回退，不得静默
  当作生效。
- **数值等价口径**：选择结果优先逐元素一致；bf16 并列差 < 1 ulp 记为已知
  噪声；评分精度不可擅自降级。
- **异步错误兜不住**：适配层「非 OOM 异常→告警回退」只覆盖同步异常，
  `ACL stream synchronize failed` 类异步错误在 stream 同步处才浮现，不在
  try 作用域；OOM 要显式 raise，避免静默降级污染 A/B。
- **后处理工程**：排序走 topk 内核（整型 ArgSort 掉 AI CPU）；用 `scatter`
  + `view/amax` 代替会回退 AI CPU 的 `scatter_reduce`；grep 运行日志的
  `npu_cpu_fallback` 找后处理热点。
