# 手段 → 场景映射

把 profiling / memory 拆解出的瓶颈类别,映射到对应的调优手段。**先有拆解
再查表**;每个手段附其适用条件与反例,一次只上一个、同节点背靠背复测。

## 按瓶颈类别

### 计算瓶颈（Cube/Vector/FA 占比高）

| 手段 | 适用 | 反例 / 注意 |
|---|---|---|
| 融合算子替换 | 多个小算子串联、后处理碎、有 AI CPU 回退 | 算子约束（头数/dtype/形状）不满足则逐调用回退，收益归零；见 `fused-ops.md` |
| 排序走 topk 内核 | 升序/取前 k 场景 | 整型 ArgSort 无 AI Core 实现会掉 AI CPU；float32 排序再转回 |
| 数据类型/布局 | 多余的 fp32 升精、非连续张量 | 评分精度不可擅自降级（并列翻选超容差）|
| 去同步/去主机回读 | `.item()`/`bool(x.any())` 等强制流同步 | 数据相关的主机检查会同步整条流水，无分支 where 化通常更优 |

### 通信瓶颈（TP/DP/EP/CP/PP 未掩盖占比高）

| 手段 | 适用 | 反例 / 注意 |
|---|---|---|
| 计算通信重叠 | 通信未被计算掩盖、串行等待 | 重叠需额外缓冲，显存紧时权衡 |
| 并行度重排 | 某并行轴通信成本畸高 | 改并行度影响显存与算子支持度，须同口径复测 |
| fix-router / EP 调度 | MoE 路由不均、dispatch 热点 | 负载均衡与数值一致性权衡 |
| 通信域/算法选择 | all2all vs ring、Ulysses vs 混合 | 跨拓扑不可比，同机背靠背 |

### 显存瓶颈（峰值触顶 / OOM）

| 手段 | 适用 | 反例 / 注意 |
|---|---|---|
| 激活重算（全量/选择性） | 激活显存大、算力有余 | 选择性重算需防缓存张量就地改写（见 SAC 开关）；CPU 上无意义 |
| 激活/参数 offload（swap） | HBM 紧、有 host 带宽余量 | swap 的 wait_load/offload 次序与流同步要正确 |
| 行/块分块 | 单次算子中间张量过大 | 分块数过多则固定开销摊薄不动，需扫参 |
| 输出复用 / 原地（谨慎） | 明确非缓存张量 | 缓存张量就地改写会被 SAC 严格校验拦截 |

### Free / 优化器瓶颈

| 手段 | 适用 | 反例 / 注意 |
|---|---|---|
| 优化器 offload | 优化器状态占显存大 | 更新阶段 host 往返成本 |
| 调度/下发优化 | Free 占比高、下发气泡 | 需 profiling 确认是下发而非等待 |

## 自动策略调优

当手段空间大、需系统搜索时，用 `autoresearch` skill 做有界自动实验：声明
目标文件、基准命令与正确性门禁，逐个手段 keep/discard/crash，审计留档。
适合「单文件可改、有确定性门禁、指标可解析」的算子/后处理类调优。

## 固定纪律

- 一次一个手段；同节点背靠背复测；跨时段/跨池 A/B 无效。
- 上手段前用机理算账 sanity-check：该手段针对的瓶颈占步时多少，收益上限
  是多少；量级不合先怀疑测量。
- 负结果最易是假的：先确认手段真生效（正面标记），再下「无效」结论。
