# 单机常见 bug 类与首因特征

可在单卡/单机复现的常见 bug，及其首因特征与定位要点。来自真实事故沉淀，
随实践补充。总原则：定位**首因**，不追末端症状；先建可证伪假设再动手。

## 环境伪装成逻辑错

| 症状 | 首因特征 | 要点 |
|---|---|---|
| CPU UT 跑 `backward` 抛 `aclInit 507008` | 非重入 checkpoint 的 recompute 为注册的 npu 设备重放 autocast → `is_bf16_supported`→`_lazy_init`，无卡机崩 | 本地无 torch_npu 不复现；CPU 用例跳过设备侧重算，或存根该探测 |
| 「卡死」在第 0 步超 20 分钟 | 新算子形状首次 AOT 编译耗时极长 | 查 kernel 缓存目录时间戳/进程 CPU 占用确认是否在编译，别当死锁改代码；提高执行超时 |
| 部分 rank 无 Traceback | torchrun 输出截断，不是真无栈 | 从 config dump 反推、看各 rank 日志，别据截断假象下结论 |

## 数值错

| 症状 | 首因特征 | 要点 |
|---|---|---|
| loss 平线/不收敛、命中率恒 0 | 监督目标双重移位（labels 预移位 + 模块内再移位）| 对齐探针逐值核对 targets 与 input_ids 的偏移 |
| 选择/路由翻转、缓慢不收敛 | 评分精度擅自降级（bf16 点积），相消放大翻选超容差 | 评分保持参考 fp32；bf16/fp16 翻选比例可量化 |
| 下游全 NaN | 首个 NaN 在上游某算子（除零/溢出/非法 index）| 开溢出检测定位首个 NaN 源，不追末端 |

## 性能错（单卡可见）

| 症状 | 首因特征 | 要点 |
|---|---|---|
| 某后处理异常慢 | 整型 ArgSort / scatter_reduce 回退 AI CPU | grep 日志 `npu_cpu_fallback`；排序走 topk 内核 |
| gather 远低于带宽 | 逐位置高级索引（fancy indexing）慢路径 | 换 `index_select`；孤立对拍复核段归因 |
| 优化看似无效 | 干预没真生效（回退路径）| 先确认正面生效标记，再下「无效」结论 |

## 方法论（反例警示）

- **猜测式 kernel/代码修补零效**：基于症状推测的修补（无条件填充、放宽
  初始化）多半无效甚至引入新错；先做能证伪的对照实验再动代码。
- **段归因被同步边界污染**：带 sync 的分段计时会把邻段开销记到当前段头上；
  用孤立对拍复核（如 einsum「90ms」实为 2ms，是同步放大）。
- **负结果最易是假的**：干预没生效和干预没奏效在记录上长得一样；下结论前
  先验开关。
