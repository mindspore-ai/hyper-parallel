# DeepSeek-V3.2 Model-Family Integration

**English** | [简体中文](README.zh.md)

DeepSeek-V3.2 adds DeepSeek Sparse Attention (DSA) to the DeepSeek-V3 MLA + MoE architecture: in every layer a
lightning indexer selects `index_topk` keys for each query (2048 in the released config), and MLA attends only to
those keys. HyperParallel trains the native Transformers `DeepseekV32ForCausalLM`; this directory provides its module
replacements, parallelization rules and training recipe.

## Registration Identity

| Item | Value |
|---|---|
| HyperParallel family name (`models/<family>/` directory and registration identity) | `deepseek_v32` |
| HF `config.model_type` | `deepseek_v32` |
| HF `architectures` | `DeepseekV32ForCausalLM` |
| Implementation source | Native Transformers implementation (`transformers.models.deepseek_v32`), `trust_remote_code: false` |

## Directory Structure

```text
models/deepseek_v32/
├── __init__.py
├── adapter/
│   ├── conversion/
│   │   └── module_replacement.py    # Replacement factories: RMSNorm, DSA attention, GroupedExperts
│   ├── distributed/
│   │   └── context_parallel.py      # DSA context-parallel wrapper
│   ├── policies/
│   │   └── sharding.py              # TP sharding rules for MLA and the indexer
│   ├── materialization.py           # Restores the RoPE buffers after weights load
│   └── registration.py              # ModelAdapterSpec
├── generated/                       # Model source generated by codegen, used only with codegen: true
└── recipes/
    ├── run_parallel_offline.sh      # Launches train_parallel_offline.yaml on 8 NPUs
    ├── train.yaml                   # Single-process recipe for the released checkpoint
    └── train_parallel_offline.yaml  # Eight-rank recipe for an 8-layer crop
```

## Features

- **NPU module replacements**, selected by the recipe's `plan_overrides`: `*.input_layernorm`,
  `*.post_attention_layernorm` and `model.norm` use the fused `RMSNorm`; `*.self_attn` uses `DeepseekV32DSAAttention`,
  which runs the indexer and the sparse attention through CANN fused operators; `*.mlp.experts` uses `GroupedExperts`.
- **Parallelism**: FSDP, TP (with loss parallelism), CP and EP. PP and sequence parallelism are not supported.
- **Training behavior** follows the Transformers implementation:
  - the router selects experts with `e_score_correction_bias` (sigmoid scores, group-limited top-k), and the bias keeps
    its initial value;
  - there is no load-balancing loss;
  - the MTP layer (layer 61) of the released checkpoint is ignored and not trained;
  - the indexer is not trained, because its output only feeds the non-differentiable top-k selection.
- **Data**: each row is one causal sequence. DSA does not read the contents of `attention_mask`, and supports no padding
  mask, dropout or KV cache.

## Requirements

- Transformers with `deepseek_v32`: `requirements.txt` requires `transformers>=5.11.0`; validated with 5.13.1.
- Ascend NPU with CANN and `cann_ops_transformer` for the DSA operators; see the
  [functional README](../../components/functional/README.md#deepseek-v32-dsa).
- Weights: `from_pretrained` loads the released FP8 checkpoint directly (it is dequantized while reading) as well as BF16
  checkpoints. The layer-61 MTP weights are ignored with a warning.

## Usage

### Train with the recipe

```bash
torchrun --standalone --nproc_per_node=1 \
  scripts/train_lm.py hyper_parallel/models/deepseek_v32/recipes/train.yaml \
  --model.pretrained_model_name_or_path=/path/to/DeepSeek-V3.2 \
  --dataset.model_assets.tokenizer.pretrained_model_name_or_path=/path/to/DeepSeek-V3.2
```

Trailing arguments override YAML fields, for example `--training.train_iters=200`.

### Multiple devices

Set the topology with command-line overrides. The recipe's `when: cp` entry enables the DSA context-parallel wrapper
when `cp_size > 1`. For EP, add a `when: ep` entry that matches only the MoE layers, i.e. `model.layers.<i>.mlp.forward`
for `i >= first_k_dense_replace` (layers 3–60 in the released config):

```yaml
plan_overrides:
  - match: "model.layers.[3-9].mlp.forward"
    when: ep
    replace:
      kind: method
      implementation:
        _target_: hyper_parallel.distributed.expert_parallel.recipes.deepseekv3_ep_compute_fn
        use_grouped_gemm: true
        overlap_shared_expert: true
  # Repeat the entry with match: "model.layers.[1-9][0-9].mlp.forward" for layers 10-60.
```

For example, eight devices with TP2 × CP2 × DP2 and EP4:

```bash
torchrun --standalone --nproc_per_node=8 \
  scripts/train_lm.py <your recipe> \
  --accelerator.tp_size=2 --accelerator.cp_size=2 --accelerator.ep_size=4 \
  --accelerator.loss_parallel=true \
  --fsdp_config.dp_shard_size=2 --fsdp_config.edp_shard_size=2
```

Keep these constraints: `ep_size > 1` whenever `tp_size > 1`, because MoE layers shard experts only by EP;
`world_size = tp × cp × dp`; `n_routed_experts` divisible by `ep_size`; `global_batch_size` divisible by
`micro_batch_size × dp`.

### Eight-rank recipe for an 8-layer crop

`recipes/train_parallel_offline.yaml` trains an 8-layer crop of DeepSeek-V3.2 (3 dense + 5 MoE layers, 16 routed
experts, 8.40B parameters) on 8 NPUs: TP2 × CP2 × DP2, EP4 × EDP2, loss parallelism and FSDP, with all module
replacements. Create the crop from the released `config.json` and tokenizer files; the weights are random BF16:

```python
import torch
from transformers import AutoConfig, AutoModelForCausalLM, AutoTokenizer

source, target = "/path/to/DeepSeek-V3.2", "/path/to/DeepSeek-V3.2-8layer-crop"
released = AutoConfig.from_pretrained(source)
config = AutoConfig.from_pretrained(
    source, num_hidden_layers=8, n_routed_experts=16,
    # Slice the per-layer types: their names differ between Transformers versions.
    layer_types=released.layer_types[:8], mlp_layer_types=released.mlp_layer_types[:8],
)
del config.quantization_config
torch.manual_seed(1234)
AutoModelForCausalLM.from_config(config, dtype=torch.bfloat16).save_pretrained(target)
AutoTokenizer.from_pretrained(source).save_pretrained(target)
```

The data is an Indexed Dataset (`.bin`/`.idx`) tokenized with the DeepSeek-V3.2 tokenizer; see the
[offline preparation guide](../../../docs/guide/data/offline_preparation_guide.md). Pass the checkpoint directory and
the dataset prefix without the extension; trailing arguments override YAML fields:

```bash
bash hyper_parallel/models/deepseek_v32/recipes/run_parallel_offline.sh \
  /path/to/DeepSeek-V3.2-8layer-crop /path/to/dataset_text_document
```

The log, data cache and checkpoints go to `output/deepseek_v32` unless `OUTPUT_DIR` is set.
